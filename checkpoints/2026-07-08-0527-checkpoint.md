## Lessons learned

- **Wheel baked caches are path-specific.** The 4 baked `__mojocache__` (`_core_mojo`,
  `_kv_cache_ops`, `_distributed_ops`×2) come from a *Klein (Graph-API)* warm venv. A
  **modulev3** arch (Z-Image, uses the experimental interpreter) additionally JIT-compiles
  **~25 `max/_interpreter_ops/__mojocache__/*.so`** on its FIRST render → **~5.5-min
  first-render hang** on a fresh wheel install, even though model+graph compiled at load.
  Correctness unaffected (wheel render byte-identical to source). Now captured in the
  `custom-max-packaging` memory.
- **Z-Image variations (`num_images>1`) crash is a one-spot bug**: the per-step **timestep
  is passed as shape `[1]`, never broadcast to `num_images`** → `symbolic dimension
  'batch_size' for input 2 does not match`. Everything else (latents, embeds, symbolic-batch
  graph, VAE) already batches. Fix site: `pipeline_z_image.py:_prepare_timestep_broadcast`
  (945) / `run_transformer` (419).
- **Dynamic batching blocker for Z-Image = the Qwen3 text encoder hard-asserts
  `batch_size==1`** (`qwen3_modulev3/text_encoder/model.py:165-191`, has a "TODO: lift this").
- **The offline profiler (`simple_offline_generation`) can't run modulev3 models** without
  bazel-dep additions: needed `z_image_modulev3` in BUILD (added, committed) AND the runtime
  `max._interpreter_ops` (a rabbit hole) — so no kineto trace for Z-Image. Coarse split is
  enough: denoise ~81%, ~137 ms/step.
- **`model.py:load_model` would corrupt NVFP4 scales**: its dtype loop cast any float tensor
  to bf16 → would turn f8 `weight_scale` / f32 `weight_scale_2` into bf16. Fixed to preserve
  quant-tensor dtypes (caught by reading, not a crash).

## Decisions made

**Choice:** How to source NVFP4 Z-Image weights.
**Picked:** Adapt the staged ComfyUI file (`/mnt/mojo-max/Z-Image-Turbo-nvfp4/
Z_Image_Turbo_NVFP4.safetensors`, SECourses, uniform NVFP4).
**Why:** Its format is bit-identical to Klein's → Klein's transforms apply verbatim; only
naming + QKV-split differ. No in-repo quantizer exists.
**Alternatives:** In-repo RTN quantizer (more work); NVIDIA modelopt (deps + calibration);
the InsecureErasure repack (mixed NVFP4+MXFP8 → needs an MXFP8 kernel we don't have).

**Choice:** Whether to build MXFP8 / optimize Z-Image further.
**Picked:** No new kernel. Z-Image is near the efficient frontier (reuses Klein's optimized
W4A4 + hits the same closed attention wall). Only open lever = activation-quant dedup (~few %).
**Why:** Attention (bf16) is the big denoise chunk and fp8-attn was slower on sm_120 (closed).
MXFP8 is a memory play, not speed.

**Choice:** Z-Image steps/cfg defaults.
**Picked:** NOT baked. Reverted the tentative `default_num_inference_steps 50→8` edit.
**Why:** guidance=0 default was never implemented, and steps=8 + the shared default cfg 3.5
= the blurry combo. Production always overrides (steps=8, guidance_scale=0). The cfg lesson
is committed at `plans/decisions/0007-comfyui-vs-max-cfg-guidance.md`.
