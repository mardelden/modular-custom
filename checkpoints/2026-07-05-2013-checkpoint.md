## Lessons learned
- **This Klein checkpoint is DISTILLED → 4 steps, CFG off** (`_DISTILLED_KLEIN_NUM_STEPS`); passing
  `--num-inference-steps 28` errors. My earlier 28-step FLOP math was wrong.
- **Render (1024², offline ~1208 ms) phase split:** text_encode ~29 ms (2%), **denoise ~987 ms (81%)**,
  vae ~191 ms (16%). Transformer dominates even at 4 steps.
- **Render is ATTENTION-bound; NVFP4==bf16 render is FUNDAMENTAL.** bf16 denoise 990 ms ≈ W4A4 987 ms
  (GEMM path irrelevant); GPU util 99% (compute-bound, NOT launch-bound → CUDA graphs won't help);
  weight-size-independent (bf16 4× weights, same time → not weight-mem-bound). ⇒ dominated by
  `mo.mha.no_cache` attention (O(N²), 48 heads, ~4608 tok, bf16, no weights, same for both) + norms.
  **A faster GEMM can't reduce render latency.** NVFP4's real wins (2.6× GEMM, ¼ mem, byte-identical)
  don't show at the render.
- **Profiling method:** diffusion `profile_execute` component table is EMPTY for Klein (compiled
  graphs, not patchable). Used manual CUDA-synced (`.to_numpy()` blocks) `perf_counter` timers around
  the 3 phases in `execute()`. No `device.synchronize()` in the Python API; `.to_numpy()` is the sync.
  `nsys`/`ncu` NOT installed on max-build. Offline gen = `//max/examples/diffusion:simple_offline_generation
  --profile-timings --num-warmups 1 --num-inference-steps 4`.
- **Shared GPU:** max-serve (team bf16 Klein, `systemctl` unit, port 8000, ~83 GB) reclaims the GPU when
  it comes back up; invisible from max-build's container (`nvidia-smi` "No running processes"). User
  stopped it this session. Don't stop team serves without explicit OK.
