## Lessons learned
- **A `modular` wheel CANNOT be built from source** in this fork: the Mojo compiler, `_core.*.so`, and `libmax.so` are closed download-only binaries (`bazel/modular_wheel_repository.bzl` *downloads* them). Only Mojo kernels (`.mojoc`) and Python are rebuildable → ship as **repacked** wheels.
- **No vendor wheel ships `__mojocache__/*.so`** — MAX JIT-compiles the 4 framework ops on first serve (`mojo build --emit shared-lib`, ~5 min/op). On a *warm* box (`~/.cache/modular` populated) this is fast, so it masked the bug; a cold box hangs. Fix = bake them into the wheel.
- **`pip install modular` does NOT pull cuBLAS/cuDNN.** The box must provide the CUDA runtime. On max-build we copied max-serve's nvidia libs to `/opt/nvidia-libs` and set `LD_LIBRARY_PATH`.
- **Flag-free `--model-path` needs a per-component diffusers repo** (each component dir has exactly one encoding). A flat/mixed folder → the greedy float4 auto-detect (`max/python/max/pipelines/lib/config/model_config.py:651`) applies float4 globally → bf16 encoder/VAE break. `--model-override transformer.quantization_encoding=float4_e2m1fnx2` scopes it.
- **The shared GPU** (same UUID `GPU-929fa3b1-…`) is passed through to max-build AND max-serve AND max-klein — only one big model serves at a time; must stop the others to free VRAM.
- **Warm caches masked everything on max-build** — its `~/.cache/modular` was populated by the from-source builds, so fresh test venvs still cache-hit. Always test truly cold to catch cold-start issues.
- **The `.py` overlay diff needs the build checkout at branch HEAD** — a lagging HEAD once dropped `vae_flux2.py` → washed-out render.
- Graph cache (`~/.cache/modular/.max_cache`) is **per-model+config**; kernel `__mojocache__` is **per-venv** (`site-packages/max/**/__mojocache__`).

## Decisions made
**Choice:** how to run our custom kernel on sm_120.
**Picked:** materialize→dense CUDA kernel (dequant FP4→bf16 transient + existing bf16 GEMM) reusing upstream's W4A16 seam.
**Why:** correct + VRAM win at ~bf16 speed with no new PTX; modeled on the AMD/Apple siblings.
**Alternatives:** native sm_120 `mma.sync` block-scaled FP4 (Phase D) — rejected for now (multi-week PTX work; deferred).

**Choice:** how to distribute the custom MAX.
**Picked:** repacked pip wheels (vendor binaries + our `.mojoc` + our `.py`), published to `/mnt/wheelhouse/max`.
**Why:** from-source wheel impossible (closed binaries); repack is a real `pip install`, disk-light, multi-container.
**Alternatives:** from-source `bazelw run` (needs source+bazel+12GB cache on each box), tarball+import-path, container image — rejected as heavier/less clean.

**Choice:** fix the cold-start kernel hang.
**Picked:** bake the 4 `__mojocache__/*.so` into the wheel via `WARM_VENV_SP` harvest.
**Why:** deterministic/hash-named `.so`, portable, self-contained; kills the ~20-min cold JIT.
**Alternatives:** ship a shared cache on `/mnt/packages` — kept as optional follow-up for the ~2.7-min graph compile only.
