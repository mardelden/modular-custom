## Lessons learned

- **P1 was truly one-spot.** No output-path or plumbing changes needed — the
  tokenizer already emits N distinct-noise latents, embeds already broadcast, and
  the base pipeline already slices `num_images_per_prompt` per request. The only
  miss was the per-step timestep rank. Distinct md5s confirm the tokenizer draws
  independent noise per batch row (variations are real, not copies).
- **`pkill -f "max serve"` over ssh kills your own ssh shell** — the remote
  `bash -c '…'` argv contains the string "max serve", so `-f` matches it and drops
  the connection (exit 255). Kill by port-listener PID or a pattern like
  `bin/max` that won't match the wrapper. (Bit me once this session.)
- **Driver `Tensor` is native (`max._core.driver.Tensor`)** — its integer-index
  rank-reduction semantics are opaque, so I built explicit rank-1 `[batch_size]`
  per-step tensors on the host rather than slicing a 2D `[T,B]` device tensor and
  trusting `t[i]` to drop a rank. Safe and cheap (T tiny tensors, cached once).
- **Source serve compiled fast** (~14 s to ready) because bazel + `__mojocache__`
  (incl. the ~25 modulev3 `_interpreter_ops`) were warm from the prior session's
  source serve — so no 5.5-min first-render hang this time.

## Decisions made

**Choice:** Whether to implement P2 (dynamic batching) autonomously while the user
is away.
**Picked:** No — deliver P1 only; leave P2 as an explicit go/no-go.
**Why:** The plan itself says "confirm the throughput win is wanted before
investing." Investigation confirmed P2 is multi-part (executor restructuring +
Qwen3 text-encoder batch-lift: 2D tokens + batched causal/pad mask + uniform
padding + graph recompile) with **cross-prompt contamination risk** that needs a
numeric-equivalence gate and ideally human review, for **modest ROI**
(compute-bound, ~1.5× only sub-MP). Landing that unreviewed is the wrong risk
tradeoff. There is no value-adding partial P2 (same-prompt batching = P1 already).
**Alternatives considered:** Implement full P2 (rejected: risk/ROI, user away);
do executor restructuring only (rejected: useless without the text-encoder lift).

**Choice:** How to get the change onto the GPU box for testing.
**Picked:** Commit to feature branch `feat/zimage-batching`, push to the fork
`origin`, `git checkout` on max-build, source-serve.
**Why:** Pure-Python change → no kernel rebuild; git is the established sync path.
Isolated from `main`/`upstream`, fully reversible, no wheel/deploy side effects.
